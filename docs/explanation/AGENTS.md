# `docs/explanation/`

An explanation doc carries reasoning: why a structure or a partition is shaped the way it is, which alternatives lost and on what grounds, and what the model deliberately does not solve. It describes the model, never a moment in time.

Keep each doc on a concept, not an integration: a question whose answer names the tracker, shell, picker or forge `work` speaks to belongs in the reference docs or the README.

Open one when a change would work against a design decision, or when the same *why* keeps being re-derived.
